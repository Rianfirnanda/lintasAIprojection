Metodologi & tata kelola

Dashboard ini hanya bagian paling ujung. Di belakangnya ada rangkaian proses yang mengumpulkan, memeriksa, dan menganalisis data harga setiap hari.

Alur kerja

Sumber data→Pengambilan→ Integrasi→Penyimpanan→ Quality gate→Analisis AI→ Dashboard→Keputusan TPID→ Umpan balik

Arsitektur (implementasi di GitHub)

  • Sumber: BPS (survei harga), pasar/pedagang (formulir petugas luring-ke-daring), Pemda (harga/stok/distribusi), AI Data Finder (penemuan kandidat sumber), Big Data sah (cuaca Open-Meteo, kalender hari raya; kandidat PIHPS, Panel Harga Bapanas, BMKG).
  • Integrasi: berkas CSV/Excel di data/masuk/, konektor API terjadwal (cuaca), standardisasi kode varian/pasar/wilayah/sumber dan satuan (ons/gram → kg).
  • Penyimpanan: data mentah disimpan apa adanya sebagai berkas di repositori, hasil olahan disimpan sebagai JSON, setiap berkas dicatat checksum SHA-256-nya, dan riwayat git menjadi jejak audit sekaligus cadangan.
  • Quality gate: deduplikasi, data hilang, batas kewajaran, pencilan, rekonsiliasi antar-sumber, validasi manusia, ketepatan waktu.
  • Analisis AI: baseline, proyeksi 14 hari, interval prediksi, deteksi anomali, rolling-origin backtesting, drift, konteks otomatis.
  • Layanan: dashboard GitHub Pages, sinyal prioritas, GitHub Issues untuk tindak lanjut, notifikasi Telegram/email, buletin mingguan/bulanan/triwulanan, indikator kinerja SMART, pengaduan & survei kepuasan, unduhan CSV.

Jadwal otomatis

  • Pipeline berjalan setiap hari kerja sekitar pukul 11.45 dan 15.45 WIB, serta setiap kali ada berkas baru di data/ atau config/.
  • Konektor cuaca diperbarui pada setiap jalannya pipeline terjadwal.
  • Sinyal anomali berkeparahan tinggi dibuatkan GitHub Issue (maks. 5 per jalan) untuk verifikasi dan tindak lanjut.
  • Mode pemantauan intensif: H-14 hingga H+3 hari raya.
  • Notifikasi sinyal prioritas dan buletin mingguan ke Telegram/email (bila secret diatur).
  • Pemeriksaan uptime dashboard setiap jam (workflow Uptime).

Peran pengguna

  • Petugas lapangan: mencatat harga di Input Harga, mengekspor CSV.
  • Operator data: mengunggah CSV ke data/masuk/, memantau hasil periksa.
  • Analis/validator: memutuskan antrean quality gate, memverifikasi sinyal.
  • TPID: membaca dashboard, menindaklanjuti sinyal lewat Issues, memberi status.

Peran AI dalam sistem

  • AI Data Finder (discovery): agen AI gratis (Gemini dengan pencarian Google lewat secret GEMINI_API_KEY, atau GitHub Models tanpa pencarian web sebagai cadangan) mencari kandidat sumber sesuai komoditas, wilayah, dan periode; keluaran terstruktur (nama, URL, periode, satuan, frekuensi, metode akses, lisensi). Setiap URL dicek: apakah muncul di hasil pencarian dan apakah dapat dibuka. Semua kandidat wajib diverifikasi analis. Dijalankan manual dari tab Actions → AI Data Finder.
  • Validasi & konteks: aturan quality gate dan konteks otomatis (cuaca, hari raya, wilayah pembanding, stok) untuk setiap sinyal.
  • Analitik: model statistik yang transparan dan dapat diaudit (naif, rerata bergerak, Holt damped trend, profil hari raya). Model hanya dipakai bila terbukti lebih baik dari baseline pada backtest.
  • Persetujuan manusia: sinyal dan rekomendasi tidak otomatis menjadi keputusan; status verifikasi dicatat.

Membaca Iris Harga (beranda)

  • Setiap batang mewakili satu varian, dikelompokkan per komoditas searah jarum jam. Panjang batang menunjukkan selisih harga terakhir dari harga normal (median 28 hari), dengan skala 2 px untuk setiap 1%.
  • Lingkar tengah adalah harga normal. Batang merah yang mengarah ke luar berarti harga di atas normal, batang biru ke dalam berarti di bawah normal, dan abu-abu berarti selisihnya kurang dari 1%. Lingkar tipis menandai ±10%, ±20%, dan ±30%.
  • Batang terang sudah melewati ambang kelompoknya (pokok dan pabrikan 5%, protein 10%, volatil 15%) dan diberi angka. Selisih lebih dari ±30% dipotong dan diberi dua garis melintang, tetapi angka yang tertulis tetap angka sebenarnya.
  • Titik merah menandai sinyal prioritas tinggi. Angka di tengah lingkaran adalah jumlah varian yang sedang di luar pola normal. Klik atau tekan Enter pada batang untuk membuka grafiknya.

Wilayah

Kabupaten Bengkulu Tengah adalah satu-satunya target pemantauan. Kabupaten Kepahiang (sentra produksi) dan Kota Bengkulu (pusat konsumsi) hanya dipakai sebagai konteks rantai pasok dan pembanding, sesuai kajian: harga Bengkulu Tengah ≈ harga Kepahiang + biaya angkut + margin + premi risiko.

Komoditas

10 komoditas pangan utama dan 21 varian dominan konsumsi mengikuti Tabel 2 Rancangan Aksi Perubahan. Sembilan item tambahan dari kajian 21 Bapokting (ikan, terigu, kedelai, tempe, SKM, garam, mi instan, margarin) sudah tersedia di config/komoditas.csv dengan aktif=0 dan dapat diaktifkan bila diputuskan.

Privasi & keamanan

  • Repositori dan situs bersifat publik: jangan pernah mengunggah nama, NIK, nomor HP, atau alamat pedagang. Berkas dengan kolom semacam itu ditolak otomatis.
  • Kunci API disimpan sebagai GitHub Secrets, tidak pernah di kode atau situs.
  • Hak ubah data dikendalikan lewat hak akses kolaborator repositori dan (disarankan) aturan perlindungan cabang main.

Yang masih perlu dipastikan

  • Daftar komoditas final (10/21 Rancangan vs 21 Bapokting kajian).
  • Sumber Big Data eksternal final dan izin pengambilan otomatis (PIHPS, Panel Harga Bapanas).
  • Batas kewajaran harga per varian dan koordinat pasar (saat ini nilai awal/perkiraan).
  • Tanggal hari raya berstatus perkiraan (menunggu SKB 3 Menteri).
  • Kebijakan publikasi: apakah data per pasar dan diskusi tindak lanjut boleh publik.
